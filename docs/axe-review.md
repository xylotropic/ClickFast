# AXe source review for iPhone Sprint

Reviewed November 11, 2026. Primary source: [cameroncooke/AXe, commit `d8ddf406d391882943e27211562ae57012ad2f7d`](https://github.com/cameroncooke/AXe/tree/d8ddf406d391882943e27211562ae57012ad2f7d). This pins the inspected main-branch content, not a claim about a released binary. No AXe controller was installed, built or run against the phone for this review. No AXe source has been copied into Sprint by this review.

## Decision

**Keep the current XCTest runner while adopting AXe's useful validation, output and measurement ideas. Investigate its runner-free physical HID/screenshot route separately. Do not replace the whole backend on source inspection alone.**

AXe genuinely controls physical iPhones through Xcode-managed CoreDevice services, without installing a signed XCTest control runner. That could simplify first-time phone setup. However, AXe's documented physical accessibility read costs roughly one second plus 44 ms per element, can take 20 seconds, and is not its simulator agent mode. Those costs could erase the intended speed advantage for accessibility-driven general control. These are AXe's recorded measurements, not measurements on our phone. [Device support](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/docs/device-support.md), [physical read budget and projection](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalAccessibility.swift)

The lightest useful transfer is a handful of algorithms in the existing three-tool interface, not the simulator framework stack, every CLI command, continuous video or an additional mandatory model.

## What really works on a physical iPhone

The physical route resolves a hardware UDID through CoreDevice JSON, verifies pairing, Developer Mode, developer disk image, tunnel and lock state, then verifies the remote service directory belongs to that exact UDID. It uses Xcode's existing tunnel rather than creating a new one. [Inventory](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/CoreDeviceInventory.swift), [readiness](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/DeviceReadiness.swift), [service directory](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/DeviceServiceDirectory.swift)

| Capability | Physical mechanism | What it means for Sprint |
| --- | --- | --- |
| Touch, keys, Home | Retained `com.apple.coredevice.hid.indigo` RemoteXPC connection | Candidate runner-free input backend; real touch sequences and cleanup |
| Screenshot | `com.apple.coredevice.screencaptureservice`, PNG | Candidate on-demand fallback, with display/orientation validation |
| Display geometry | `com.apple.coredevice.deviceinfo` | Logical point, pixel scale and orientation must be distinguished |
| AX tree / point / restricted semantic press | `axAuditDaemon.remoteAXService` speaks DTX despite its service advertisement | More complex and potentially slow than the local XCTest AX traversal |
| Rotation | CoreDevice orientation request plus display readback | Useful optional capability; no need for first minimal version |
| H.264 | Native display service plus UDP/RTP/RTCP | Efficient for video, unnecessary for default control; stream ownership conflicts |

These mechanisms are traced in AXe's own [protocol record](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/docs/device-protocols.md), [RemoteXPC transport](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/RemoteXPCConnection.swift), [input owner](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalDeviceInputOwner.swift) and [media capture](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalDeviceMediaCapture.swift).

The physical broker holds RSD/HID/AX state between CLI calls. Its local socket verifies same-user executable identity and build identity, allows one input lease, rejects a busy device, releases owned input on client departure, and stops after idle. This avoids reconnecting for each warm command. It skips repeated CoreDevice readiness reads only for a short interval after input the broker itself sent; failures and Lock end that fast path. Copy the ownership concept, not the exact 25-second assumption into a different transport. [Broker owner](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalDeviceBrokerOwner.swift), [client](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalDeviceBrokerClient.swift), [server](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalDeviceBrokerServer.swift)

Physical AX reads receive InitialDump plus AdditionalData, validate their graph relationship, and refresh the raw DTX connection because repeating the subscription can replay old data. Projection may make live attribute requests. It also suppresses missing custom-action lookups because per-key requests made software-keyboard screens too slow. This is a concrete warning against assuming that a cached channel means a cheap fresh tree. [AX session](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/DeviceAccessibilitySession.swift), [archive admission](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalAXTreeArchive.swift), [projection](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Packages/IDBKit/FBSimulatorControl/Commands/FBPhysicalAXTreeProjection.swift)

Physical limitations are material: agent snapshots/refs and selected-display mode are refused; text uses US HID keycodes with a 256-byte limit and does not support arbitrary Unicode; clipboard and sliders are refused. `--tap-style physical` in simulator agent tests describes touch style on a simulator, not physical-phone agent support. The current hardware test app needs iOS 27.1 SDK or later, while our existing environment uses Xcode 26.5/iOS 26.5; compatibility of an extracted physical backend here is unverified. [Physical reference](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/agent-plugin/skills/axe/references/physical-device-reference.md), [device command boundary](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalDeviceCommand.swift), [hardware suite requirements](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/scripts/run-e2e-devices.sh)

For the urgent same-app overlay bug, a fresh point query and retained native identity may be cheaper than comparing an entire screen twice. Measure both. A visible-tree fingerprint is useful context, but animations, clocks and counters should not force unrelated target retries. Reject a covered target immediately; don't retry it five times. Never resolve an old ref to a different control merely because its label matches.

Focus-and-type deserves its own two-phase contract: first focus the chosen field, then re-read and confirm that the same field owns focus before sending exact text. Keyboard-driven frame movement can be expected while field replacement is not. Preserve separate delivery receipts: a focus tap delivered followed by typing refused is not an entirely unsent operation. [Focus-and-type plan](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Utilities/AgentFocusAndTypePlan.swift)

Copying a generic global-settle loop would work against Sprint's purpose. Its physical batch also parses/validates each step when reached rather than validating the whole high-level batch first; retain Sprint's stronger upfront validation and stop-on-first-failure behavior. [Controller](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Utilities/AgentModeController.swift), [physical batch](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Utilities/Batch/PhysicalDeviceBatch.swift)

## JEV: useful patterns, selective adoption

AXe includes a real agent runner and TypeSafe client. Useful ideas are one request containing operation/target/text heads, deterministic bypass for an unambiguous sole candidate, exact text supplied by the higher-level agent, strict answer validation, bounded steps/calls, no-progress detection, and a retained network session. It can overlap a remote decision with a freshness read, then validate the current target before dispatch. These are hypotheses to benchmark on our phone, not free speedups. [Policy](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXeCore/AgentPolicy.swift), [TypeSafe client](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXeCore/TypeSafeClient.swift), [simulator agent runner](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Agent/SimulatorAgentRunner.swift)

Do not import the whole autonomous runner: it has simulator-specific execution, fixed waits in parts of its loop, and completion decisions that are weaker than independently verifying a real post. Keep JEV optional, a bounded action selector over live candidates, and record every billed request including discarded decisions. Keep the default setup free of an extra API dependency. See [JEV research](jev.md) for current TypeSafe API details and limitations.

## Defer or exclude

- **Whole AXe/IDBKit framework stack:** valuable for multi-simulator automation, but the executable depends on two built IDB frameworks, ArgumentParser and bundled resources. Extracting a minimal physical transport is a separate project; its dependency closure and real compiled footprint must be measured. [Package manifest](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Package.swift), [build script](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/scripts/build.sh)
- **Duo/selected-screen/hinge/simulator lifetime stacks:** not capabilities of this physical phone. Their context binding, cleanup and coordinate ideas transfer; their private simulator APIs do not.
- **Continuous H.264/video by default:** adds ownership, packets, decoding and shutdown work. AXe documents one native device video stream and replacement conflicts with Xcode Device Hub, plus delayed shutdown. Use optional evidence capture only, outside latency trials where possible. [Display stream](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Device/PhysicalDeviceDisplayStream.swift), [device support](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/docs/device-support.md)
- **US-HID-only text:** a regression for Unicode captions, emoji and general app use. Do not swap out the current text path until exact caption correctness is tested.
- **Global device settings, simulated locations/status bars, Siri/Apple Pay/lock:** outside the immediate speed goal; no automatic changes to the user's security or app settings.
- **Large fixture app and whole E2E matrix:** use a small focused fixture for bugs, plus actual TikTok/Reel flows. AXe itself documents that its full simulator suite takes hours.

## Benchmark lessons and required evidence

AXe's published comparison uses three simulator tasks, three repetitions per tool, app setup/launch outside the timer, official tool skills and manual final review. It is not a physical-device comparison or a JEV ablation. The result notes disclose omitted large raw artifacts, task familiarity in one competitor skill, and grader fixes followed by rescoring. Its ratios cannot be transferred to this project. [Published result and limits](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/benchmarks/results/2026-11-11-official-skills/README.md), [manual review](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/benchmarks/results/2026-11-11-official-skills/manual-review.md)

Adopt its provenance and independent readback practices, then strengthen them for this task:

1. Pin controller source/build, phone/iOS/app/Xcode versions, model and chooser, prompts/skills, task inputs and grader revision. Record the transport and whether Mirroring/XCTest were fully isolated.
2. Keep raw immutable attempt records privately. Preserve failed, blocked and uncertain trials; distinguish input delivery, visible effect and independently verified completion. Store sanitized summaries publicly.
3. Use alternating trial order for comparable reversible tasks. Report cold startup/provisioning, warm driver latency, full agent wall time, app processing/upload and human authentication separately.
4. Test same-PID overlay insertion, replaced same-label controls, moved frames, keyboard coverage, stale queued commands, cancellation before/after input, lost reply after mutation, observation failure after successful input, and no-motion scrolling. Assert that refused input had no effect.
5. Check text exactly: Unicode, emoji, multiline, punctuation, length and focus. Check video identity/crop/audio and destination account/audience, not just a successful tap.
6. For a candidate runner-free backend, first compare cold/warm coordinate tap plus verified effect, one screenshot, AX read at small/large/keyboard screens, repeated Home/app navigation, cleanup latency, resident CPU/RSS and build/install bytes. Shut down the existing XCTest controller before running it. No concurrent-controller benchmark is valid.
7. Compare the three controller strategies on the same direct backend: agent per step, agent-generated short batches, and optional JEV local loop. Report success rate, p50/p95, tool/model turns, failed taps, recovery, payload bytes and costs together.

Actual TikTok publication and Instagram Reel behavior remain governed by the user's current instructions. A saved Instagram draft must be reported as a draft, and must not be shared to complete a benchmark when the user has said never to share it. Never repeat an uncertain publication. Private screenshots, captions, accounts, videos and post URLs stay outside the public repository.

AXe's hardware harness is especially useful because it verifies taps against recorded coordinates, typing against the actual field value, and video against changing on-screen markers; it also checks that refused post-rotation taps have no effect and cleans up capture processes on failures. Those fixture checks diagnose the driver; they do not replace real app acceptance. [Physical harness](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/scripts/test-physical-devices.py), [physical fixtures](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Tests/PhysicalDeviceFixtureTests.swift)

## Licensing and provenance before copying

AXe's root code is MIT with Cameron Cooke's notice. Its IDBKit carries Meta's MIT notice. Copying substantial portions requires preserving the applicable notices and license text. [AXe LICENSE](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/LICENSE), [third-party notices](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/THIRD_PARTY_LICENSES), [IDBKit LICENSE](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Packages/IDBKit/LICENSE)

The keyboard-observation signal/threshold adaptation is an exception: AXe attributes it to Apache-2.0 sim-use and bundles LICENSE/NOTICE/ADAPTATION. Copying that material entails retaining those documents and applicable attribution and marking modifications; the root MIT label does not remove those requirements. Prefer the existing native keyboard rectangle for coverage rather than importing heuristic thresholds. Trace source-specific provenance, including RuntimeSnapshot's stated XcodeBuildMCP origin, before copying any substantial helper. [Adaptation record](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXe/Resources/licenses/sim-use/ADAPTATION.md), [RuntimeSnapshot](https://github.com/cameroncooke/AXe/blob/d8ddf406d391882943e27211562ae57012ad2f7d/Sources/AXeCore/RuntimeSnapshot.swift)

Keep Apple's private framework declarations as build inputs where appropriate, not redistributable code/assets assumed to be covered by AXe's root MIT grant. AXe's manifest explicitly excludes those headers from release resources. No GPL implementation is needed: AXe says its physical protocol implementation comes from its own captured protocol record rather than pymobiledevice3.

## Implementation order

Fix target identity/coverage and native command expiry first; preserve mutation outcome and cancellation semantics; then reduce observation payload and add bounded no-motion scrolling. Rerun focused phone tests after each relevant change. Finish the current app tests under the user's exact sharing constraints. Only then spend effort on an isolated runner-free transport experiment if measured setup/latency or reliability warrants it. Publish scoped evidence, not a claim of universal speed.

## Sprint follow-through after this review

Implemented and tested: re-read the same native target and reject changed meaning/frame, disabled or off-screen targets;30-second native snapshot expiry; explicit delivery receipts after observation errors; navigation-only output; stale-context invalidation; optional bounded TypeSafe chooser with external opt-in. These are selective adaptations, not a wholesale copy of AXe. Full point ownership, queued native expiry beyond snapshot TTL, and propagated cancellation/held-input cleanup remain open.

The official v2.0.2 release was subsequently tested with XCTest stopped: three physical AX reads succeeded, while screenshot and HID service advertisements were unavailable. See `benchmarks/axe-device.json` and `benchmarks/STATUS.md`. The source-review statements above describe the review itself; they do not substitute for these device findings.
